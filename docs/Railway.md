# ORBIT на Railway (без GitHub)

Папка `deploy` собирается командой `python tools/make-deploy.py`: только нужные файлы, без состояния и журналов (папка `runtime` в неё не попадает). Деплой делается вручную, по шагам ниже; из GitHub тоже можно (в корне лежит `railway.json`).

## Как это устроено

Рынок живёт в облаке, а GPT и Claude запускаются **на вашем компьютере** через ваши входы по подпискам. Облако их не запускает и ваших входов не получает.

1. Облако ставит запросы моделей в очередь.
2. Программа-исполнитель на вашем компьютере (`orbit/worker.js`, запуск через `Запустить исполнителя моделей.cmd`) забирает запросы по HTTPS, запускает `codex` и `claude` и возвращает ответы.
3. Облако применяет решения к рынку, как и раньше: режимы «Раунды» и «Свободная торговля», пробуждение по событию и толпа ботов работают так же.

Исполнитель выполняет **только** то, что умеет сам: запрос содержит лишь текст и название семейства модели, а команду и флаги исполнитель задаёт сам. Разрешены только `gpt-6-luna` и `claude-haiku-5-5`, Codex стартует в режиме «только чтение» без командной оболочки, Claude без инструментов. Задание с любой другой моделью, семейством или лишними полями отклоняется или игнорируется. Пароль вводится скрыто и нигде не сохраняется.

- **Без исполнителя** облако показывает «Исполнитель не подключён»; толпа ботов при этом работает. Запуск с моделями без исполнителя отклоняется с понятным сообщением.
- **Нужно, чтобы окно исполнителя оставалось открытым** на время прогона. Закрытие окна отключает модели; идущий прогон их агентов остановится с ошибкой «Исполнитель не забрал запрос».
- **Лимиты подписок** тратятся на вашем аккаунте, как и при локальном запуске; пять моделей одного семейства делят лимиты.
- **Облачная биржа начинает с нуля** (такт 0); ваш локальный эксперимент остаётся на компьютере.

## Открытый вход (без пароля на сайте)

С переменной `ORBIT_OPEN=1` сайт открывается без окна пароля. Пароль `ORBIT_TOKEN` остаётся **только для исполнителя моделей** на вашем компьютере: без него кто угодно мог бы подключить к бирже свою «модель». Чтобы вернуть пароль на сайт, удалите переменную `ORBIT_OPEN` (`railway variable delete ORBIT_OPEN`).

Что это значит на практике: любой, у кого есть адрес, видит биржу и может запускать и останавливать толпу ботов. Запуск **с моделями** возможен, только пока у вас открыто окно исполнителя: тогда чужой запуск потратит лимиты ваших подписок. Поэтому адрес не публикуйте, а окно исполнителя закрывайте, когда модели не нужны. Запросы с чужих страниц по-прежнему блокируются.

## Переменные окружения

| Переменная | Значение | Зачем |
|---|---|---|
| `ORBIT_TOKEN` | длинный случайный пароль (от 12 символов) | Пароль входа (HTTP Basic, имя пользователя любое) и пароль исполнителя. Без него сервер на сетевом адресе не запустится, если не задан `ORBIT_OPEN=1`. |
| `ORBIT_OPEN` | `1` | Открытый вход: сайт без пароля, пароль нужен только исполнителю. |
| `ORBIT_HOST` | `0.0.0.0` | Слушать все интерфейсы. Порт Railway задаёт сам через `PORT`. |
| `ORBIT_MODELS` | `remote` | Модели запускает исполнитель на вашем компьютере. `off` полностью отключает модели, значение по умолчанию запускает их на самом сервере (только для локального сервера). |
| `ORBIT_DATA` | `/data` | Папка постоянного тома: состояние и журналы. |

Защита: все страницы и запросы, кроме `/health`, требуют пароль; канал исполнителя требует ещё и служебный заголовок, чтобы им нельзя было управлять с чужой страницы; пять неверных паролей подряд блокируют клиента на минуту (пустой запрос за окном ввода не считается); запросы на запуск принимаются только с того же адреса; заголовки против встраивания в чужие страницы. Пароль передаётся по HTTPS, который даёт Railway.

## Шаги

Все команды выполняются в PowerShell. Вход в Railway у вас уже выполнен (`railway whoami`).

1. Сгенерировать пароль и сохранить его (в чат или в файлы проекта его вставлять не нужно):

```powershell
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

2. Создать проект и сервис, привязать папку:

```powershell
cd deploy
railway init --name orbit
railway add --service orbit
```

3. Постоянный том и переменные (подставьте свой пароль вместо `<ПАРОЛЬ>`):

```powershell
railway volume add --mount-path /data
railway variable set ORBIT_TOKEN=<ПАРОЛЬ> ORBIT_HOST=0.0.0.0 ORBIT_MODELS=remote ORBIT_DATA=/data --skip-deploys
```

4. Загрузить и запустить (без GitHub, прямо из папки), затем получить адрес:

```powershell
railway up --service orbit
railway domain
```

5. Открыть выданный адрес, ввести любое имя и пароль, выбрать «Запустить толпу» и время (до 1440 минут). Журнал сервера: `railway logs`.
6. Для моделей запустите на компьютере `Запустить исполнителя моделей.cmd`, введите адрес и пароль. В блоке «GPT + Claude Code» появится «Исполнитель: подключён».

## Ограничения и заметки

- **Одна реплика.** Состояние лежит на томе одного экземпляра; масштабировать в несколько реплик нельзя. При каждом деплое сервис кратко перезапускается, а активный прогон прерывается; состояние до последнего сохранения (не старше 15 секунд) остаётся на томе.
- **Толпа не продолжается после перезапуска сама.** Как и локально, запуск нужно нажать заново.
- **Адрес с паролем в строке** (`https://имя:пароль@...`) не используйте: браузер запрещает такие запросы из страницы. Вводите пароль в окне входа.
- **Обновление версии:** пересоберите папку (`python tools/make-deploy.py`) и повторите `railway up`. Том и пароль сохраняются.
- **Стоимость.** Нагрузка небольшая (300 ботов считаются за доли секунды), но Railway тарифицирует время работы сервиса и том; смотрите свой тариф.
- **Удаление.** Проект и том удаляются в панели Railway или командой `railway volume delete`; делайте это только осознанно.
